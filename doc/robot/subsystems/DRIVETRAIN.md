# Drivetrain Subsystem (`Swerve`)

[`Swerve`](../../src/main/java/io/github/frc461/rowdy25/subsystems/drivetrain/Swerve.java) extends CTRE Phoenix6's `SwerveDrivetrain<TalonFX, TalonFX, CANcoder>` and implements WPILib's `Subsystem`. It is *both* the hardware abstraction (modules, gyro, kinematics, odometry threads) and the orchestration layer that produces every `pathFindTo*` `Command` used by teleop bindings and the [`AutoManager`](../autos/AUTO_MANAGER.md).

The companion classes ([`Song`](#song-orchestra-helper), [`SwerveSim`](#swervesim-physics-simulation), [`SwerveTelemetry`](#swervetelemetry-telemetry-dispatch)) handle music, simulation, and telemetry respectively.

## Construction

```java
super(
    TalonFX::new, TalonFX::new, CANcoder::new,
    SWERVE_DRIVETRAIN_CONSTANTS,
    FRONT_LEFT, FRONT_RIGHT, BACK_LEFT, BACK_RIGHT
);
```

The `SwerveDrivetrain` super constructor takes factory references for motors and encoders so that Phoenix6 can build hardware abstractions itself; the four module constants are generated by CTRE Tuner X and live in `Constants.SwerveConstants`. The four-module geometry, kinematics, and high-frequency odometry thread (Phoenix6's `OdometryThread`, which samples module positions at ~250 Hz independently of the 50 Hz main loop) are all set up inside the super.

Then the Rowdy25-specific wiring:

- `currentMode = IDLE`, `autoHeading = true`, `consistentHeading = 0` initialize the drive-mode state machine.
- `Song.playRandom(this, Song.startupSongs)` — Plays an Orchestra tune through the eight drive/azimuth TalonFXs at startup.
- `if (Utils.isSimulation()) new SwerveSim(this).startSimThread()` — Spins up the Maple-style physics simulation thread only when running in the Gradle simulation context.
- **`AutoBuilder.configure(...)`** — Wires PathPlanner's auto builder against this drivetrain:
  - pose supplier → `localizer::getStrategyPose`
  - pose reset → `localizer::setPoses`
  - chassis-speeds supplier → derived from the module-state kinematics
  - apply-speeds consumer → `SwerveRequest.ApplyRobotSpeeds` with the per-wheel feedforward forces from PathPlanner
  - controller → `PPHolonomicDriveController` with the translation/rotation P-only PIDs from `SwerveConstants`
  - flip-when-red supplier → `Constants.ALLIANCE_SUPPLIER.get() == Red`
  - subsystem requirement → `this`
  This registration is needed for any code path that *does* call `AutoBuilder.pathfindToPose` / `followPath` (PathPlanner-authored autos, the warmup commands in `RobotContainer`, etc.), even though Rowdy25's `pathFindTo*` helpers do not.
- **`motorStalling` / `moduleStuck`** — For each of the four drive motors, a `BooleanSupplier` watches `getStatorCurrent() > SLIP_CURRENT`. A `Trigger` debounces that supplier for 250 ms and ANDs it with `|chassis velocity| < 0.1 m/s && |ω| < 0.25 rad/s`. The result is a per-module "stuck" trigger that fires only when the wheel is *trying* to spin (current is up) but the chassis is *not* moving — i.e., the wheel is bound up against an obstacle. `isStuck()` returns true if any module is in this state. This is what powers the coral-station obstruction fallback in `RobotStates.coralStationState`.

## `DriveMode` enum

12 modes. The first four (`IDLE`, `ROTATING`, `FAST_ROTATING`, `TRANSLATING`) are pure teleop joystick interpretations. The remaining eight are "auto-heading" modes that lock the chassis rotation to a vision/landmark target while the driver retains translation control:

- `BRANCH_HEADING`, `BRANCH_L1_HEADING` — face the nearest reef branch (L1 has a separate mode because the trough is angled differently).
- `REEF_TAG_HEADING`, `REEF_TAG_OPPOSITE_HEADING` — face the nearest reef AprilTag, or face directly *away* (used when removing low algae, where the manipulator pokes backward).
- `OBJECT_HEADING` — face the best PhotonVision color detection (coral or algae).
- `CORAL_STATION_HEADING`, `PROCESSOR_HEADING`, `NET_HEADING` — face the named landmark.

`DriveCommand` reads `currentMode` every tick to decide whether driver rotation input applies or is replaced by a PID-locked target heading. `isFullyTeleop()` returns true only for the first four modes; the rest indicate the driver is "trusting" an auto-heading lock.

`isAutoHeading()` returns the boolean flag toggled by `toggleAutoHeading()`; this is a **separate** axis from the `DriveMode` enum because the driver may *be* in `BRANCH_HEADING` mode but with auto-heading disabled (only the heading hint is published, no PID lock). The A-button chord in [`RobotContainer`](../ROBOT_CONTAINER.md) flips this flag in lockstep with `Localizer.trustCameras`.

## Swerve Requests

Three CTRE `SwerveRequest` objects are reused (re-applied each tick rather than allocated):

- `fieldCentric` — translation in field frame + rotation in chassis frame.
- `robotCentric` — translation in chassis frame; used by the partner-push command.
- `xMode` — `SwerveDriveBrake`, the X-stance defensive lock.

`applyRequest(supplier)` is a thin wrapper that returns `run(() -> setControl(supplier.get()))`. `forceStop()` issues a zeroed `fieldCentric` request with `OpenLoopVoltage` (skipping closed-loop ramps) — the only safe immediate-stop.

## `pathFindTo*` family

Every member of this family wraps a [`PathfindToPoseAvoidingReefCommand`](../commands/DRIVE.md) (often followed by a [`DirectMoveToPoseCommand`](../commands/DRIVE.md) final approach), inside `Commands.defer(supplier, Set.of(this))`. The `defer` is essential:

- The target pose for branches, stations, algae, etc. is read from `localizer.nearest*` fields **at command-schedule time**, not at object-construction time. If we eagerly captured the pose in the constructor, every press of LB during a match would re-target the same branch the bumper-press chose during `robotInit()`.
- `Set.of(this)` declares the requirement so the deferred command is exclusive with `DriveCommand` (the default).

### Coral station family

`pathFindToLeftCoralStation` / `pathFindToRightCoralStation` interpolate between the AprilTag-anchored center pose and the FAR_LEFT/RIGHT preset offset by 0.25 (a 1:3 lerp toward the far corner). They terminate on either:

- `isStuck() && |currentPose - nearestRobotPoseAtCoralStation| < 5 * TRANSLATION_TOLERANCE_TO_ACCEPT` — wheels-bound-and-close-enough, *or*
- `intake.coralEntered()` — beam-break confirmed a coral.

In parallel, `WaitUntilCommand(robotStates.atTransitionStateLocation(CORAL_STATION)).andThen(toggleCoralStationState(true))` arms the coral-station superstructure mid-flight so the mechanism is in position by the time the chassis docks.

The `*GroundIntakeCoral` variants are paired with `setObjectHeadingMode` and stop 2.0 m short of the far-corner pose at a 10° angle, where the color camera has the widest FOV onto the station. They then chain into `directMoveToObject` for the final approach to a detected coral.

### Branch family

`pathFindToNearestLeftBranch` / `pathFindToNearestRightBranch` use `localizer.nearestRobotPosesNearBranchPair` (a tuple of the two nearest branches' pre-branch standoff poses) and finish with `DirectMoveToPoseCommand` once the chassis enters the transition-tolerance window. The direct-move max velocity is clamped to **2.5 m/s when the current auto-level is L4** and to `MAX_VEL` otherwise — L4 is the tallest extension and the most tip-prone, so the final approach goes slower.

`pathFindToScoringLocation` is the *autonomous-grade* variant used by `AutoManager`: it takes an explicit `ScoringLocation` + `Level`, calls `setCurrentAutoLevel(level)` so the superstructure pre-arms, and uses `RobotPoses.Reef.getRobotPoseNearBranch / getRobotPoseAtBranch`. It also waits with a debounced `nearStateLocation(L4_CORAL)` trigger (1 s debounce) before triggering the actual outtake — protecting against transient state changes during the final docking.

### Algae family

`pathFindToNearestAlgaeOnReef` and `pathFindToAlgaeOnReef(side)` follow the pattern:

1. Pathfind to the "near" reef pose.
2. Race a `DirectMoveToPoseCommand` against `intake.algaeStuck` — the intake reports stuck when the algae jams the gripper.
3. Back off via a second `DirectMoveToPoseCommand` (timeout 0.5 s) — this pulls the algae *away* from the reef without rotating, freeing it from the structure.
4. Stow.

In parallel, the algae-state transition is fired once the chassis enters the transition tolerance, with the high/low choice determined by `localizer.nearestAlgaeIsHigh` (or `FieldUtil.Reef.Side.algaeIsHigh(side)` for the explicit-side overload).

### Net / Processor

`pathFindToNet(randomized)` lerps to the net target. The `randomized` flag picks `localizer.randomizeNetScoringPose()` (per-call random X) vs. `localizer.centerNetScoringPose()`. The final `DirectMoveToPoseCommand` uses `localizer.randomizedRobotPoseAtNet` (which is the most-recently-computed random pose, stored on the localizer so the trigger arming sees the same target).

`pathFindToProcessor` is the simpler twin — single target, single direct-move, no randomization.

### `pushAlliancePartnerOut`

`applyRequest(robotCentric.withVelocityX(-1.0)).withDeadline(waitSeconds(0.5)).andThen(forceStop)` — drives backward at 1 m/s for 500 ms then stops. Used in the autonomous "Push" preference to nudge a stalled alliance partner off the start line.

## `directMoveToObject`

Wraps `SearchForObjectCommand` (see [`AUTO.md`](../commands/AUTO.md)) with a 2.5 m/s cap. Spotting the object and the approach are inside `SearchForObjectCommand`'s state machine; `Swerve` only provides the entry point.

## `periodic()`

Per tick:

1. **Operator perspective.** First time (or whenever disabled), call `setOperatorPerspectiveForward(BLUE_DEFAULT_ROTATION / RED_DEFAULT_ROTATION)`. This tells CTRE which way "field forward" is for field-centric input; flipping it on alliance change is what makes the joystick "up" always mean "away from your driver station." The `hasAppliedDefaultRotation` latch and the disabled-only re-apply prevent the perspective from flipping mid-match if the DS briefly reports an alliance change.
2. **Heading sync while disabled.** `localizer.syncRotations()` realigns the pose estimator's heading to the gyro's raw reading. Done during disabled because vision can drift the heading and we want pre-match resets to bring us back to truth.
3. **Orchestra.** Plays a random disable-songs track while disabled (until 10-second mark), stops it on enable.
4. **Telemetry / Localizer.** Forwards to `swerveTelemetry.publishValues()` and `localizer.periodic()`.

## `Song` (orchestra helper)

[`Song`](../../src/main/java/io/github/frc461/rowdy25/subsystems/drivetrain/Song.java) holds lists of `.chrp` filenames bundled in `deploy/orchestra/` and exposes `playRandom(swerve, list)`. The Orchestra mechanism is CTRE's audio playback over TalonFX phase current, which is why the swerve drive motors are the speakers. The 10-second check protects against orchestra noise leaking past the start of a match (FRC rules disallow audio after the buzzer).

## `SwerveSim` (physics simulation)

[`SwerveSim`](../../src/main/java/io/github/frc461/rowdy25/subsystems/drivetrain/SwerveSim.java) runs a dedicated thread that integrates a simplified vehicle model (Phoenix6 module-level `SimState` updates, gyro integration) at ~200 Hz so the Gradle `simulateJava` workflow gives a responsive driving feel. The fidelity is intentionally minimal — enough to validate command flow and telemetry, not a substitute for the practice field.

## `SwerveTelemetry` (telemetry dispatch)

[`SwerveTelemetry`](../../src/main/java/io/github/frc461/rowdy25/subsystems/drivetrain/SwerveTelemetry.java) publishes module states, kinematics, drive-mode, and the `consistentHeading` value to NetworkTables and DogLog every loop. The specific topic names are enumerated in the source; the docs treat the telemetry layer as a flat reference rather than reproducing the topic table.

## Implementation note on tuning

The PID gains for the PathPlanner holonomic controller, the slip-current threshold for `motorStalling`, the 250 ms debounce on `moduleStuck`, the 2.5 m/s L4 cap, and the choreographed timeouts (0.5 s back-off, 1 s debounces) were all tuned through practice-field iteration. The math here is straightforward; the numbers are the result of measurement.
